# VK AI-бот

Чат-бот ВКонтакте (и локальная консоль) с AI на базе GPT-4o Mini через ProxyAPI, плюс модуль новостей ГАРАНТ ПРАЙМ.

## Возможности

- Приветствует нового пользователя по имени
- Отвечает на сообщения с помощью GPT-4o Mini, с историей диалога (контекстные ответы)
- Распознаёт новостные запросы («что нового по охране», «изменения в законодательстве» и т.п., независимо от падежа/числа слов) и присылает подборку новостей ГАРАНТ ПРАЙМ по готовым пресетам (охрана / налоги и бухучёт / всё сразу), с учётом периода («за неделю» / «за месяц» / «за 3 месяца» — по умолчанию неделя)
- В VK-версии под каждым сообщением бота — постоянная клавиатура для новостей ГАРАНТ (по одной кнопке на строку, чтобы текст не обрезался на смартфоне): «🛡 Охрана — месяц», «📋 Главные новости — месяц», «📅 Свой период» (запрашивает даты текстом в формате ДД.ММ.ГГГГ-ДД.ММ.ГГГГ, с любым периодом и темой). Кнопка — это просто предзаполненный текст, обычный ввод продолжает работать точно так же
- **Важно про VK-клавиатуры**: они появляются только если в настройках сообщества включены «Возможности ботов» (Управление сообществом → Сообщения → Возможности ботов). Без этой настройки VK отклоняет отправку клавиатуры — бот автоматически подстраховывается и присылает тот же текст без кнопок, а не молчит
- Один и тот же функционал доступен и через VK, и через локальную консоль — оба интерфейса работают поверх общего ядра

## Установка

Полная пошаговая инструкция (локально и на удалённом сервере, включая запуск как systemd-сервиса) — в [INSTALL.md](INSTALL.md). Коротко:

```bash
git clone <репозиторий>
cd задание_9_vkbot_парсер

# Создание виртуального окружения
python -m venv .venv

# Активация
# Windows (PowerShell):
.venv\Scripts\Activate.ps1
# Windows (CMD):
.venv\Scripts\activate.bat

# Установка зависимостей
pip install -r requirements.txt

# Браузер для модуля новостей ГАРАНТ ПРАЙМ (см. раздел "Модуль новостей" ниже)
playwright install chromium
```

## Настройка

1. Создайте сообщество ВКонтакте: https://vk.com/editapp?act=create
2. Включите в настройках сообщества обработчик сообщений (LongPoll API)
3. Получите токен сообщества
4. Зарегистрируйтесь на https://proxyapi.ru и получите API-ключ
5. (Опционально, для новостей ГАРАНТ) — один из двух вариантов доступа: логин и пароль для входа на demo.garant.ru, либо токен официального API ГАРАНТ Коннект (`https://api.garant.ru`)

Создайте файл `.env` в корне проекта:

```
VK_TOKEN=ваш_токен_сообщества
PROXYAPI_KEY=ваш_ключ_proxyapi

# Для модуля новостей ГАРАНТ ПРАЙМ (см. раздел "Модуль новостей" ниже) —
# два независимых режима, можно задать один или оба.
GARANT_LOGIN=
GARANT_PASSWORD=
GARANT_TOKEN=

# Необязательно: явный выбор режима (browser/api/mcp). Если не задано —
# режим определяется автоматически по тому, какие переменные заполнены
# (см. раздел "Модуль новостей" ниже).
GARANT_MODE=
```

Без `GARANT_LOGIN`/`GARANT_PASSWORD`, `GARANT_TOKEN` и `GARANT_MODE` бот продолжает работать как обычно — на новостной запрос он ответит «изменений не найдено» (источник недоступен без учётных данных), при этом весь остальной функционал (диалог, приветствие) не затрагивается.

Проект построен как **ядро + тонкие интерфейсы**: вся бизнес-логика не знает, что такое VK или консоль, а работает с абстрактными `IncomingMessage` / `OutgoingMessage`.

```
  history.py                   — DialogueHistory (интерфейс) + InMemoryDialogueHistory (лимит по числу сообщений)
  dialogue_service.py          — DialogueService: история + AIClient

```

### Модуль новостей ГАРАНТ ПРАЙМ — два режима подключения

Есть два независимых, равноправных способа получать новости ГАРАНТ ПРАЙМ, и явный механизм выбора между ними:

- **`browser`** — headless-браузер (Playwright), вход на `https://demo.garant.ru/#/startpage:1` по логину/паролю (`GARANT_LOGIN`/`GARANT_PASSWORD`). Реализация — `core/news/parser_browser.py` (`GarantPrimeParser`).
- **`api`** — официальный REST API ГАРАНТ Коннект (`https://api.garant.ru`), по токену (`GARANT_TOKEN`). Реализация — `core/news/parser_api.py` (`GarantApiParser`).
- **`mcp`** — зарезервировано на будущее (сервис `mcp.garant.ru`, обёртка над тем же REST API через Model Context Protocol). Каркас класса есть (`core/news/parser_mcp.py`, `GarantMcpParser`), но режим **не реализован** — при `GARANT_MODE=mcp` бот громко логирует ошибку конфигурации и продолжает работать без новостного модуля (не падает).

Оба рабочих режима реализуют один и тот же интерфейс `NewsParser` (`core/news/parser_base.py`, контракт `fetch(query) -> list[NewsItem]`) — `DialogueService`, `BotCore` и интерфейсы VK/консоли не знают, какой режим используется.

**Выбор режима** — `core/news/parser_factory.py` (`get_news_parser()`), вызывается один раз при сборке зависимостей в `main.py`:

1. Если задан `GARANT_MODE` — используется он, и без нужных для него данных это ошибка конфигурации (`GARANT_MODE=api` без `GARANT_TOKEN`, `GARANT_MODE=browser` без логина/пароля, или `GARANT_MODE=mcp`) — она **явно логируется как ERROR** при старте, бот не падает, а работает без новостного модуля (тихого отката на другой режим нет — раз режим указан явно, значит его и ожидали).
2. Если `GARANT_MODE` не задан — автоопределение по приоритету: (1) задан `GARANT_TOKEN` → `api`; (2) иначе заданы оба `GARANT_LOGIN`+`GARANT_PASSWORD` → `browser`; (3) иначе — новостной модуль отключён (прежнее поведение «изменений не найдено», без регрессий).

**Фильтрация по теме/территории/виду информации в режиме `api`.** Дерево категорий ГАРАНТ (`GET /v2/prime`) организовано по двум осям верхнего уровня — подтверждено живым вызовом 09.09.2026: **«Вид информации»** (федеральное/региональное законодательство, судебная практика; территория, например «г.Москва», лежит вложенно внутри «Региональное законодательство» этой же ветки — не отдельный параметр API) и **«Сфера интересов»** (предметные темы, например «Частная сыскная и охранная деятельность», «Налоги»). Резолюция ключевых слов в ID узлов — единый переиспользуемый механизм (`core/news/category_tree.py`, поиск по основам слов, тот же приём, что у `IntentRouter`), используется для `NewsQuery.topic` (ветка «Сфера интересов»), `.territory` и `.info_type` (обе — «Вид информации»). **Важное правило ГАРАНТа**: категории из разных осей в одном вызове дают пересечение (AND), а не объединение. Первая версия этой логики (09.09.2026) при одновременном использовании темы и территории/вида информации объединяла (union) результаты двух отдельных запросов — реальное тестирование в тот же день показало, что и объединение (тонет в региональном шуме на периодах от месяца), и пересечение (0 результатов даже за неделю — документы редко помечены одновременно и темой, и конкретным регионом) дают плохой результат для этой пары осей. Итоговое решение: **если задана тема — территория/вид информации в запрос не попадают вообще**, используется только тема; территория/вид информации применяются как фильтр только когда темы нет (см. докстроку `GarantApiParser`, п.2, и раздел «Найденный и исправленный баг фильтрации» ниже). `authority`/`doc_type`/`keywords` **не поддерживаются** ни одним из режимов в этой итерации — у метода «Лента Прайм» нет для них реального параметра (единственный подтверждённый механизм — язык запросов метода «Поиск», `POST /v2/search`, не реализован); если эти поля заданы — `GarantApiParser` логирует одно предупреждение и игнорирует их, не падает.

Кроме трёх готовых пресетов (охрана / налоги-бухучёт / всё сразу), бот распознаёт и **произвольную тему, введённую текстом в чате** — например, «новости по строительству» — и резолвит её тем же механизмом по дереву категорий (`IntentRouter._extract_custom_topic`, `presets.py:preset_custom_topic`). Это расширение сверх исходного ТЗ, добавленное по запросу пользователя.

**Дата новости в режиме `api`.** В отличие от `browser` (дата читается напрямую со страницы, `.primeDate`), ответ официального API (`POST /v2/prime/create-news`) **не содержит даты** ни у новости, ни у документа — подтверждено по `https://www.garant.ru/mobileonline/api/documentation/`. Выбрано: `NewsItem.published_at` заполняется правой границей запрошенного периода (`date_to`), одинаковой для всех новостей одного запроса — не требует дополнительных обращений к API. Точная дата отдельной новости (через `GET /v2/topic/$topic` на каждую новость) реализована как выключенная по умолчанию опция конструктора (`fetch_exact_dates`) — не включена и не проверена end-to-end в этой итерации, т.к. кратно увеличивает число запросов к API и подпадает под отдельный лимит (не более 300 запросов этим методом в календарный месяц).

**Ограничения периода в режиме `api` — два независимых правила.** API ограничивает и **ширину** одного вызова (`toDate - fromDate` ≤ 10 дней, `MAX_CHUNK_DAYS`), и, отдельно, **глубину** периода (`fromDate` не может быть раньше года от сегодняшней даты, `MAX_LOOKBACK_DAYS`). `GarantApiParser.fetch` сначала усекает период до годовой границы (если весь период старше года — не делает HTTP-вызовов вообще), затем разбивает оставшееся на интервалы ≤10 дней (с паузой между запросами) и объединяет результаты — прозрачно для пользователя, без ошибки 400. Если интервалов больше `MAX_CHUNKS_PER_FETCH` (≈4 месяца) — берутся только последние из них, с отдельным предупреждением в лог (не путается с усечением по годовой границе).

**Статус проверки.** `browser` подтверждён end-to-end через реальный VK-бот (06.09.2026) — реальный пользователь написал боту «изменения в законодательстве за месяц» и получил настоящий отформатированный список новостей ГАРАНТ ПРАЙМ (10 из 20 найденных документов, с заголовками, описаниями, датами и ссылками). По пути к этому результату обнаружены и решены четыре нетривиальных момента:

1. Поля логина/пароля на `account.garant.ru` — React-контролируемые, `page.fill()`/`page.type()` не сохраняют значение, поэтому используется посимвольный ввод через `page.keyboard.press()`.
2. Обычный headless-браузер Playwright почти всегда получал редирект на страницу «уже используется» — оказалось, что это **обнаружение автоматизации** (`navigator.webdriver === true`, `HeadlessChrome` в User-Agent). Подтверждено сравнением с обычным браузером пользователя (там всё работало сразу). Решается библиотекой `playwright-stealth`, которая маскирует признаки автоматизации, плюс имитация человеческого поведения — случайные паузы 1-5с и движение мыши перед кликами (`_simulate_human_pause`).
3. Сайт также буквально просит не логиниться слишком часто одним и тем же аккаунтом («Ваш логин и пароль уже используются. Попробуйте войти через несколько минут.») — штатный анти-abuse кулдаун. `GarantPrimeParser` учитывает это сам: внутренний кулдаун между попытками входа (`MIN_SECONDS_BETWEEN_LOGINS = 60`) и блокировка от одновременных вызовов.
4. **Финальная и решающая находка**: `page.wait_for_load_state("networkidle")` ненадёжен на demo.garant.ru — на странице постоянно открыт WebSocket виджета поддержки (`wss://chat.garant.ru/...`), из-за которого страница может никогда не становиться по-настоящему "сетево-простаивающей". Заменено на точечные `wait_for_selector` для конкретных элементов (поле логина, вкладка «Новости ПРАЙМ», карточки новостей) — именно это дало стабильный результат.

Реальная разметка ленты «Общая лента ПРАЙМ» (`.primeDate` + `.primeDocument`/`.documentTitle`/`.annotationText`) зафиксирована в `_parse_html` и покрыта тестами на офлайн-фикстуре (`tests/fixtures/garant_prime_sample.html`), составленной по образцу настоящей страницы — без обращения к сайту при запуске тестов. Что ещё не сделано: применение самих фильтров `NewsQuery` (дата/тема/орган) через UI вкладки — сейчас `fetch()` читает ленту по умолчанию (обычно последние ~3 месяца), без выставления фильтров сайта под конкретный запрос; см. `TODO` в `core/news/parser_browser.py`, включая перспективный маршрут `/#/fresh/DD.MM.YYYY;DD.MM.YYYY` для фильтрации по периоду напрямую через URL.

`api` **проверен живым вызовом 09.09.2026**: `GET /v2/prime` с реальным `GARANT_TOKEN` вернул настоящее дерево категорий — подтвердил и точные названия веток («Вид информации», «Сфера интересов»), и вложенность территории (например, «г.Москва» внутри «Региональное законодательство»), и реальные узлы темы охраны («Частная сыскная и охранная деятельность», не «Охранная деятельность», как было раньше в пресетах, — `presets.py` обновлён по результатам этой проверки). `POST /v2/prime/create-news` подтверждён end-to-end через реальный VK-диалог — включая найденный и исправленный по горячим следам баг (см. ниже). Метод «Поиск» (`POST /v2/search`, вне рамок этой итерации) при той же проверке **не удалось вызвать успешно** — оба опробованных адреса (`/v2/search`, `/search`) вернули не-JSON ошибку (400/404 уровня веб-сервера, не JSON-ответ API) — точный адрес/форма этого метода для v2 остаются неподтверждёнными, уточнить отдельно перед будущей реализацией метода «Поиск».

**Найденный и исправленный баг фильтрации (09.09.2026, два раунда реального тестирования).** Первый запрос («новости за неделю охранная деятельность по Санкт-Петербургу и Ленобласти») вернул 147 полностью нерелевантных новостей — фильтр фактически не работал. Причины и правки:

1. Пресеты временно ограничивали `info_type` значением «Федеральное законодательство» — эта категория огромна (почти любой новый федеральный акт), а `GarantApiParser` при нескольких осях объединял (union) результаты отдельных вызовов, поэтому объединение с ней не сужало, а фактически убивало фильтр по теме. Убрано — `info_type` больше не ограничивается по умолчанию.
2. Резолюция темы «охранная деятельность» совпадала по общим словам («деятельность», «охрана» без суффикса) с десятком посторонних узлов дерева («Страховая деятельность», «Охрана труда» и т.п.) — тема резолвилась в 10 несвязанных категорий вместо одной нужной. Добавлен блок-лист общих слов (`category_tree.GENERIC_STEM_BLOCKLIST`, пока только «деятельность»), пресет безопасности сужен до одного точного узла («Частная сыскная и охранная деятельность»).

После этого «за неделю» стало давать 1-2 релевантные новости, но повторное тестирование пользователем с периодом «месяц»/«два месяца» снова показало десятки нерелевантных региональных новостей Петербурга (выборы, антикоррупционные комиссии, детская хирургия). Причина — архитектурная: `GarantApiParser` **объединял** (union) результаты вызова по теме (узкая ось «Сфера интересов») и вызова по территории (широкая ось «Вид информации» — с ростом периода запроса регионального контента становится сильно больше, чем контента по узкой теме, и он тонет в шуме). Проверено и обратное — **пересечение** (один вызов с обоими наборами ID) для той же пары дало **0 новостей** даже за неделю: документы по охранной деятельности почти никогда одновременно помечены конкретным региональным тегом. Ни объединение, ни пересечение темы и территории/вида информации не дают надёжного результата. Итоговое решение — **тема исключает территорию**: если задана тема, территория/вид информации в API-запрос не попадают вообще, используется только тема (см. докстроку `GarantApiParser`, п.2). После этой правки тот же запрос («частная охрана» + «Санкт-Петербург») на живом API дал: за неделю — 1 новость, за месяц — 2, за два месяца — 10, почти все точно по теме.

Аудит фильтров сайта `demo.garant.ru` в режиме `browser` (см. `docs/garant-site-filters-audit.md`) не был завершён технически: попытка входа исследовательским скриптом упёрлась в «Неверные данные» — вероятная причина (не проблема с самими учётными данными) видна на скриншоте: посимвольный ввод пароля через `page.keyboard.press` без пауз иногда теряет один символ. Защитная пауза между нажатиями (`KEYSTROKE_DELAY_MS`) добавлена в `_type_into` (`parser_browser.py`) по итогам этой находки; глубокий аудит сайтовых фильтров — отдельная задача на будущее. `browser` в этой итерации остаётся без фильтрации категорий/территории — `api` (подтверждённый, см. выше) — основной режим для точной фильтрации.

## Известные ограничения

- История диалога хранится в памяти процесса (`InMemoryDialogueHistory`) — без персистентности, теряется при перезапуске. Ограничена по количеству последних сообщений (не по токенам). Структура (`DialogueHistory`) уже позволяет добавить персистентную реализацию позже без изменений в остальном коде.
- Распознавание новостных запросов — keyword-matching по основам слов (`IntentRouter`), без NLP/ML — осознанное решение для MVP. Кнопки VK-клавиатуры используют ту же логику (шлют текст, который распознаётся как обычное сообщение) — отдельного механизма callback-кнопок не реализовано.
- `GarantPrimeParser`: вход, переход на вкладку «Новости ПРАЙМ» и разбор списка новостей подтверждены end-to-end через реальный VK-бот (см. выше). Не реализовано применение фильтров `NewsQuery` (дата/тема/орган/территория) через UI сайта — `fetch()` пока возвращает ленту без фильтрации по этим полям (см. `TODO` в `core/news/parser_browser.py` и `docs/garant-site-filters-audit.md` — эмпирический аудит сайтовых фильтров не завершён, см. там причину). Встроен кулдаун между входами (60с) в рамках одного процесса — если новостные запросы приходят чаще, повторные молча пропускаются с «изменений не найдено». Кулдаун не защищает от коллизий с ДРУГИМИ процессами/скриптами, логинящимися на тот же demo-аккаунт одновременно (актуально только при параллельной отладке, не при обычной работе одного бота).
- Точная дата отдельной новости в режиме `api` (`fetch_exact_dates=True`, доп. запрос `GET /v2/topic/$topic` на каждую новость) реализована, но выключена по умолчанию и не проверена end-to-end через `BotCore` (лимит — 300 запросов этим методом в календарный месяц).
- `authority`/`doc_type`/`keywords` (`NewsQuery`) — осознанно не поддерживаются ни одним режимом в этой итерации: у метода «Лента Прайм» нет для них параметра (см. докстроку `NewsQuery` в `core/models.py`); единственный подтверждённый механизм — язык запросов метода «Поиск» (`POST /v2/search`), не реализован и не подтверждён живым вызовом (см. «Статус проверки» выше). Если эти поля заданы — они логируются как игнорируемые, не имитируются.
- Произвольная тема в чате («новости по <сфера>») — MVP-регэксп (`IntentRouter.CUSTOM_TOPIC_PATTERN`), не NLP: распознаёт только конкретные шаблоны фраз («(что) нов.../измен... по/о/об/про <тема>»), не произвольную формулировку. Резолюция темы в дереве категорий может не найти точного совпадения (тогда — самый широкий fallback по всем категориям, с предупреждением в лог).
- Территория (`REGION_KEYWORDS` в `IntentRouter`) — небольшой куратируемый список регионов (Москва/Санкт-Петербург/Татарстан), не полный справочник субъектов РФ.
- Режим `mcp` (`mcp.garant.ru`) — только архитектурная заготовка (`core/news/parser_mcp.py`, `GarantMcpParser`), реального MCP-клиента нет; `GARANT_MODE=mcp` даёт понятную ошибку конфигурации при старте, а не рабочий режим.
- Кнопка «Свой период» и явные даты в тексте (`ДД.ММ.ГГГГ-ДД.ММ.ГГГГ`) задают точный период запроса, но реального выбора даты через календарь в VK нет — обычная клавиатура VK не поддерживает такой виджет (потребовался бы отдельный VK Mini App).
- Новый интерфейс (например, Telegram) — только архитектурная точка расширения (`interfaces/_future/`), сама реализация не входит в эту итерацию.
