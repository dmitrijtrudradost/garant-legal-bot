# Аудит фильтров сайта ГАРАНТ (режим `browser`)

## Доступность доменов

Дата проверки: **10.09.2026**. Вход через SSO `account.garant.ru`, тот же `GarantPrimeParser._login_to_garant` (посимвольный ввод, `KEYSTROKE_DELAY_MS`, stealth).

| Домен | Результат |
|---|---|
| `https://internet.garant.ru/#/startpage:1` | Логин прошёл. Открылась «Система ГАРАНТ», вкладка «Новости ПРАЙМ», лента «Общая лента ПРАЙМ», панель фильтров слева. Карточек `.primeDocument` без фильтра: 20–22. Apply фильтров подтверждён в тот же день. |
| `https://demo.garant.ru/#/startpage:1` | После сессии internet сайт ответил «логин и пароль уже используются» (`alreadyused`). Отдельного успешного входа на demo в этот день не было. Не подтверждён. |

Повторный вход на internet после alreadyused проходит не раньше чем через несколько минут (эмпирически 3–5 мин после успешного входа, не 60 с).

## Панель фильтров на `internet.garant.ru` (10.09.2026)

1. **Полный список.** У групп «Вид информации», «Орган», «Тип», «Территория», «Тема» есть кнопка «Полный список». У «Вида информации» модалка с полем «Поиск», кнопки «Выбрать» / «Отмена». Это не только 3–4 чекбокса на панели.

2. **Тема.** Модалка — дерево ExtJS (папки верхнего уровня), поле placeholder **«Фильтр»**, не «Поиск». Листья в свёрнутом дереве не видны: нужен фильтр по редкому стему и раскрытие узлов. Название узла охраны на сайте — **«Частная детективная и охранная деятельность»**, в API — «Частная сыскная и охранная деятельность». Клик по подписи нужно делать внутри `.x-window`, иначе перехватывает панель (ложный клик в «Охрана труда»).

3. **Период.** Радио «За неделю» / «За месяц» / «За период». После «За период» текстовые поля `input[name=from]` и `input[name=to]`, placeholder `дд.мм.гггг`. Произвольные даты набираются текстом.

4. **Комбинирование.** 10.09.2026, одна сессия, период 03.09.2026–10.09.2026:
   - только тема охраны: `apply_topic_ok=True`, **0** карточек (сайт: «Ничего не найдено», «0 результатов»);
   - тема + территория «г.Москва»: обе оси кликаются (`extra_ok=True`), тоже 0;
   - тема + «Федеральные акты»: то же, 0.
   На пустой теме AND не отличить от «тема исключает территорию». В коде по-прежнему: если тема задана, территорию и вид информации не отмечаем.

После apply парсер обязан дождаться текста **«Лента отфильтрована»** или `.emptyMessage` / «Ничего не найдено», а не `.primeDocument` и не класса `.resetFilter`. Класс `.resetFilter` уже есть на кнопке панели рядом с «Применить фильтры» — ожидание по нему срабатывает сразу. Если после этого кликнуть «Следующая» (пагинатор ещё от общей ленты, до 299 страниц), apply сбрасывается: фильтр «за месяц» выглядит сломанным. Подтверждено 10.09.2026: без ожидания реальной отметки бот отдавал 20 общих новостей на «Охрана — месяц».

Разметка: ExtJS (`x-fieldset`, `x-form-cb-label`, `x-tree-node-text`, `widgetDateRangeField`). Селекторы в коде завязаны на видимый текст, не на id вроде `button-1110`.

Лента без фильтра: 20 `.primeDocument` на первой странице и `ul.paginator` (`Следующая`, `data-page` до 299). Это ограничение страницы сайта, не бота; `_collect_feed_pages` листает пагинатор.
